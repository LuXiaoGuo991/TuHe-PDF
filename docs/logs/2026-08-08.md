## Docker 部署修复

### 背景与根因

首个本地镜像构建成功，但 Nginx 容器因无法执行 `/docker-entrypoint.d/98-noindex.sh` 而以退出码 127 重启。原因是 `nginx-noindex.sh` 和 `nginx-ipv6.sh` 使用 Windows CRLF 换行；初次用 `nginx` 用户执行 `sed -i` 时还因目录权限失败。

### 变更

- `Dockerfile` 在最终镜像阶段保持 root，使用 `sed -i 's/\r$//'` 处理两个入口脚本，并准备 `/etc/nginx/tmp`。
- 完成准备后再设置 `USER nginx`，因此 Nginx 仍以非 root 用户运行。
- 构建使用 `npm run build`，`SITE_URL` 默认值为 `http://localhost:8080`。
- `compose.yml` 构建本地 Dockerfile，容器名为 `tuhe-pdf`，暴露端口 8080。

### 验证

- `docker compose up --build -d` 修复后成功完成。
- `docker compose ps` 显示 `tuhe-pdf` 为 `Up`，端口为 `0.0.0.0:8080->8080/tcp`。
- `Invoke-WebRequest http://localhost:8080` 返回 HTTP 200。

### 后续

- 外部部署前将 `SITE_URL` 更新为最终 HTTPS 域名。
- 保留换行规范化步骤，因为开发环境是 Windows、最终镜像是 Linux。
