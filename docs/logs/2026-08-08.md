## Docker Deployment Repair

### Background

The first local image built successfully but the Nginx container restarted with exit code 127. The entrypoint could not execute `/docker-entrypoint.d/98-noindex.sh`.

### Root Cause

`nginx-noindex.sh` and `nginx-ipv6.sh` had Windows CRLF line endings. Linux treated the shell interpreter path as invalid. An initial normalization attempt ran as the `nginx` user and failed because `sed -i` could not create temporary files in `/docker-entrypoint.d`.

### Changes

- `Dockerfile`: the final image stage now remains root while it normalizes both entrypoint scripts with `sed -i 's/\r$//'` and prepares `/etc/nginx/tmp`.
- `Dockerfile`: `USER nginx` is applied after those setup steps, so Nginx still runs without root privileges.
- `Dockerfile`: the build uses `npm run build` and defaults `SITE_URL` to `http://localhost:8080` for the local baseline.
- `compose.yml`: builds the local Dockerfile, names the container `tuhe-pdf`, and exposes port 8080.

### Verification

- `docker compose up --build -d` completed successfully after the Dockerfile repair.
- `docker compose ps` reported `tuhe-pdf` as `Up` with `0.0.0.0:8080->8080/tcp`.
- `Invoke-WebRequest http://localhost:8080` returned HTTP 200.

### Follow-up

- Update `SITE_URL` to the final HTTPS domain before external deployment.
- Keep the Dockerfile line-ending normalization because development occurs on Windows and the final image is Linux.
