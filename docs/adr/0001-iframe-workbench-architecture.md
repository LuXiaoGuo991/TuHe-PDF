# ADR 0001：iframe 工作台架构

- **Status**: Accepted
- **Date**: 2026-08-12

## Context

TuHe PDF 已有大量彼此独立的工具页。每个页面拥有自己的 HTML、初始化逻辑、文件状态和构建入口。若在工作台改造时同步切换到单页前端路由，需要重写页面生命周期、共享状态和历史地址兼容，风险会扩散到全部工具，且难以逐页回归。

目标是在保留现有工具页 URL 与运行方式的前提下，提供侧栏、标签页、首页和跨工具切换组成的桌面式工作台外壳。

## Decision

工作台使用 `index.html` + `src/js/workbench.ts` 管理外壳，每个工具页通过同源 `iframe` 装载。工具卡片打开或复用标签页；关闭标签页前由外壳检查 iframe 中的任务状态。

`workbench.ts` 在 iframe 加载后注册同源导航拦截：捕获“返回工具列表”和 Logo 点击，将其转换为 `tuhe:show-home` 消息；普通链接仅在解析后确认同源且目标为工作台首页时拦截。消息监听同时校验 `event.origin === window.location.origin`。

## Consequences

收益：

- 工具页无需为工作台迁移而重写，已有直达 URL、SEO 页面和工具内部状态继续工作。
- 单个工具故障和样式副作用被 iframe 边界隔离，可渐进迁移视觉系统。
- 外壳能够统一提供搜索、分类、标签与未完成任务关闭保护。

代价与限制：

- iframe 增加文档与运行时开销，外壳和工具页之间的状态同步必须通过受控消息或同源 DOM 访问完成。
- 跨工具链接可能在 iframe 内直接导航，标签标题不会自动同步；当前仅对返回首页导航进行拦截。
- 浏览器历史记录和深链接仍以独立工具页为主，工作台标签状态不承诺跨刷新恢复。
- 未来若改为前端路由，应先统一工具生命周期和任务状态协议，再逐步替换 iframe，而非全量一次性迁移。
