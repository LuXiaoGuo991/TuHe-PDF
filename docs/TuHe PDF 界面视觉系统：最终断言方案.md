# TuHe PDF 界面视觉系统：最终断言方案

## 一、最终定位

**TuHe PDF 应被设计为：**

> **一个可信、克制、具备桌面专业工具秩序感的本地 PDF 工作台。**

它不是营销型 SaaS，也不是花哨的在线工具集合。用户进入后应立即感受到：

- 文件在本地浏览器中处理；
- 操作过程清晰、可预期；
- 复杂能力被有序收纳；
- 视觉克制但不陈旧；
- 中文用户在工作、学习、政务资料处理时可以长时间使用。

---

## 二、唯一确定的视觉方向

### **“数字档案室 / 专业文档工作台”**

**设计关键词：**

`本地` · `可信` · `纸张感` · `精密` · `克制` · `秩序` · `低干扰`

### 明确排除

以下方向不再作为 TuHe PDF 的设计路线：

- 紫蓝渐变、霓虹发光、科技感背景；
- 玻璃拟态、半透明叠层、过度模糊；
- 大量大圆角卡片；
- 营销页式的大 Banner、夸张插画；
- 把“红色”作为提交、上传、处理的主按钮色；
- 用纯颜色而不加文字/图标表达状态；
- 每个区域都独立套厚重卡片的“卡片墙”。

---

## 三、主题策略：深色工作台优先，暖白阅读主题补充

### 1\. 默认主题：**深色专业工作台**

作为站点的默认外观，服务高频操作、文件列表、PDF 预览与夜间办公。

- 气质：石墨、纸张、金属工具；
- 对比：清晰而不刺眼；
- 重点：降低长时间使用时的视觉疲劳；
- 主色：松柏绿，而不是当前的靛蓝。

### 2\. 可选主题：**暖白阅读模式**

作为后续第二阶段功能，而不是当前重构的前置条件。

- 不使用冷纯白；
- 采用偏纸张的暖白和深墨色；
- 与深色主题共享同一套语义 token、组件结构和品牌色；
- 用户偏好仅保存在浏览器本地。

**结论：**  
先完成深色主题重构；深色主题稳定后，再通过 token 映射实现暖白主题。**不维护两套独立 CSS。**

**色彩断言：**

- **松柏绿是唯一主操作色。**
- **朱砂色是品牌记忆色，不承担普通确认操作。**
- 成功、警告、危险、信息是独立语义色，不能互相挪用。
- 任何状态都必须包含文案、图标、形状或位置变化，不能只靠颜色区分。

## 五、字体断言

### 字体分工

- 中文界面正文与标题：同源部署的 `Source Han Sans SC / 思源黑体` 子集。
- 英文、数字、版本号、快捷键、技术参数：保留 `DM Sans`。
- 首页少量品牌文案或长篇说明标题：可选用 `Noto Serif SC / 思源宋体`，仅限展示场景。

### 禁止事项

- 不使用第三方字体 CDN；
- 不用装饰字体作为工具页面正文；
- 不在一个页面混用超过两种主要字体；
- 不依赖单一 Windows 系统字体作为中文视觉的一致性基础。

## 六、布局与组件断言

### 1. 页面层级

所有高频工具页统一为：

```text
顶栏
└─ 工具上下文：工具名称 / 简要说明 / 本地处理承诺
   └─ 工作区
      ├─ 第一步：选择文件
      ├─ 第二步：参数设置
      ├─ 第三步：执行处理
      └─ 第四步：结果下载 / 后续操作
         └─ 页脚与合规链接
```

### 2. 首页

首页不再是普通工具卡片墙，而是：

1. 搜索与高频工具优先；
2. 分类作为第二层；
3. “本地处理、不上传文件”作为明确但克制的可信说明；
4. 工具卡片降低高度、降低圆角、加强信息结构；
5. 常用工具应有更高视觉权重，而不是与低频工具完全等价。

### 3. 卡片

- 普通容器圆角：**8px**；
- 浮层、弹窗、主上传区：**10px**；
- 避免常规使用 `16px` 以上圆角；
- 默认通过边框分层，阴影只用于浮层与拖拽状态；
- hover 优先改变背景和边框，不做明显上浮；
- 禁止到处使用厚投影。

### 4. 按钮

| 按钮类型 | 视觉规则                                  |
| -------- | ----------------------------------------- |
| 主按钮   | 松柏绿实底、浅色文字、明确 hover / active |
| 次按钮   | 深色或透明底、边框、主文字                |
| 文字按钮 | 无底色，仅用于低风险辅助动作              |
| 危险按钮 | 危险色，仅限删除、清空、覆盖等不可逆动作  |
| 禁用按钮 | 降低对比但仍保持可读，不只用 opacity      |

### 5. 表单与文件列表

- 输入控件默认有清晰边框；
- 聚焦时使用 `--color-focus` 焦点环；
- 文件列表遵循：**文件类型标识 → 名称 → 辅助信息 → 单项操作**；
- 删除文件必须为显式危险操作，不和普通编辑按钮同级混淆；
- PDF 预览区域使用沉下去的深表面，和参数控制区区分开。

## 七、图标、状态与动效断言

### 图标

- 以 **Lucide** 作为默认线性图标系统；
- 若已有 Phosphor 图标，逐步收敛，不在同一页面混用两套图标风格；
- 图标只承担辅助识别，关键操作必须保留文字；
- 品牌图形可以使用朱砂色，但工具功能图标以中性色或松柏绿为主。

### 状态

- 成功：绿色 + 对勾 + 明确结果；
- 警告：琥珀色 + 提示图标 + 后果说明；
- 失败：危险红 + 错误图标 + 恢复路径；
- 处理中：不使用无限转圈作为唯一反馈，应呈现阶段、进度或当前处理内容。

### 动效

- 常规交互：`120–200ms`；
- 卡片 hover：背景、边框、图标颜色的微小变化；
- 上传、处理、生成结果：使用文件流转、进度轨道或阶段动画；
- 所有动效支持 `prefers-reduced-motion`；
- 禁止无意义的大面积浮动、渐变流动和持续发光。

## 八、代码实施断言

当前项目的核心样式入口是：

```text
src/css/styles.css
```

但页面中广泛存在：

```text
bg-gray-\*
text-gray-\*
border-gray-\*
indigo-\*
```

因此**绝不进行全局颜色字符串替换**。最终实施路线固定为：

1. 在 `src/css/styles.css` 建立全局设计 token；
2. 定义公共语义组件类，例如：
   - `.ui-surface`
   - `.ui-surface-raised`
   - `.ui-panel`
   - `.ui-input`
   - `.ui-button-primary`
   - `.ui-button-secondary`
   - `.ui-button-danger`
   - `.ui-focus-ring`
   - `.ui-status-success`
   - `.ui-status-warning`
   - `.ui-status-danger`

3. 先迁移公共顶栏、侧栏、页脚、弹窗、上传区、工具卡片；
4. 选择“合并 PDF”或“压缩 PDF”作为完整试点工具页；
5. 通过试点固化组件规范，再迁移其余工具页；
6. 深色主题完成并稳定后，以 `data-theme="light"` 的 token 覆盖实现暖白主题；
7. 主题偏好仅写入浏览器 `localStorage`，不引入服务端状态。

## 九、验收标准

实施后的界面必须满足：

- 用户能在首屏明确感知“本地处理、不上传文件”；
- 主按钮、危险按钮、普通按钮之间一眼可分；
- 高风险动作具有明确确认或视觉隔离；
- 工具页操作步骤有稳定、可预测的顺序；
- 深色模式下正文、边框、禁用状态、焦点状态仍具有足够对比度；
- 键盘焦点可见；
- 移动端不因卡片和按钮过密而误触；
- 新页面不再直接新增 `gray-\*` / `indigo-\*` 作为业务视觉基础；
- 全站不依赖第三方字体、图标或样式 CDN；
- 亮色主题与深色主题共享组件结构和语义 token。

---

## 最终结论

**TuHe PDF 从现在起采用“数字档案室 / 专业文档工作台”作为唯一视觉基线：**

> **默认深色、暖石墨背景、松柏绿主操作、朱砂品牌点缀、中文优先字体、低圆角与高秩序布局、语义化 Design Tokens 驱动、先试点再迁移。**

这套方向兼顾了工具效率、本地处理的信任感、中文用户的工作环境，以及未来亮暗主题扩展的工程可维护性。
